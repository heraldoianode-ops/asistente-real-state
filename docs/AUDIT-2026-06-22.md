# Auditoría de proyecto / Project Audit — 2026-06-22

Proyecto: **Asistente-de-Real-State** · v0.8.4 · Supabase project `mh-systems-platform` (`nehfrtedwcmdlmbulhef`) · schema `asistente_real_state`.

## ES — Resumen

Auditoría de coherencia repo ↔ producción (R1/R16). Producción está **sana y coherente**, pero el repositorio estaba **desactualizado**: varias evoluciones de Fase 7/8 y una integración con Google Calendar se aplicaron directamente en Supabase sin migraciones versionadas ni registro en `features.json`.

### Hallazgos

1. **Convención de identidad (resuelve TD-008).** Un trigger `BEFORE INSERT` en `users` (`enforce_user_id_equals_auth`) fuerza `users.id := auth_user_id`. Por eso `id == auth_user_id == auth.uid()` para todos (admin y agentes). No existe el bug de scoping que se sospechó contra el repo; el repo simplemente no tenía el trigger ni `current_agent_id()`.
2. **RLS divergente.** Producción usa el helper `current_agent_id()` y políticas consolidadas (`clients_own`, `poc_own`, `events_own`, `inter_own`, `matches_own`, `wa_manage_admin`, `scraping_read`…). El repo (migración 04) tenía nombres por comando y `auth.uid()` crudo. `is_admin()` en prod filtra por `auth_user_id` (repo usaba `id`).
3. **Features no documentadas en prod.** Tablas `agent_google_credentials` y `google_oauth_states`, funciones `current_agent_id`, `enforce_user_id_equals_auth`, `update_updated_at_column` y sus triggers (`set_updated_at` en 11 tablas, `trg_user_id_equals_auth` en `users`). Es una integración **Google Calendar/OAuth** (F026) ausente del repo.
4. **Esquema `users`.** Prod tiene `auth_user_id` y `avatar_url`, sin `hashed_password`. Reconciliado (TD-007).

### Acciones aplicadas

- Nueva migración idempotente `db/migrations/07_reconcile_with_prod.sql` que declara el estado vivo (triggers, helpers, RLS consolidado, tablas Google). **No-op sobre producción**; no se ejecutó nada en prod.
- `features.json`: alta de **F026** (Google Calendar/OAuth) como DONE.
- `decisions.json`: **D017** (convención `id==auth_user_id` + `current_agent_id`; política de reconciliar repo→prod).
- TD-008 y TD-009 cerradas; queda nota de gobernanza (LOW): aplicar cambios siempre vía migración versionada.
